Global rules:
- G1 — Code only what the response says. No inference of motives, implied anchors, or unstated plans. For every field return `<field>_evidence`: a verbatim quoted span, or the literal string NONE. A non-default label with evidence NONE is invalid.
- G2 — Each field's rule is a numbered waterfall; the FIRST matching clause decides. If no clause matches, take the conservative default (the label marked DEFAULT / NONE / 0).
- G3 — Mentioning is not anchoring, and mentioning is not flagging. A source or feeling merely referenced carries no decisive weight unless the field's rule says so.

- G5 — The full scenario stems are provided with every coding task. Use them to resolve what a span refers to — which reviews, whose advice, what was prescribed, what "my original decision" was. - G7 — The anchor fields code what carries DECISIVE weight for the stated action, which need not be an information source: practical constraints and the respondent's own pending synthesis are codeable anchors in v3. Exactly one anchor label per scenario. Anchor fields code the basis of the decision PROCEDURE, never the quality of the information consulted — quality is carried by the CHECK flags.

Coding rules:

BRT1_decision
Pick exactly one: KEEP_BOOKING | CHANGE_RESTAURANT | CANCEL_OR_POSTPONE | UNCLEAR_OR_CONDITIONAL
- KEEP_BOOKING — any indicated intent to proceed with the booking tonight.
- CHANGE_RESTAURANT — any indicated intent to move the event to a different venue.
- CANCEL_OR_POSTPONE — any indicated intent to call it off or move it to another time.
- UNCLEAR_OR_CONDITIONAL — no direction indicated, or the action flips on an unresolved condition. (DEFAULT)
Rule, in order:
1. A direction of action is indicated — including hedged wording (e.g. "we'd probably still go", "I think I'd keep it") and including plans to glance at information without making the action depend on it ("I'll take a look at these reviews, but really we're gonna go whatever the case") — and NO unresolved condition is stated on which the action would flip → code the indicated action.
2. An unresolved condition is stated on which the action WOULD flip (e.g. "keep it unless the reviews check out badly", "depends what Friend A says") → UNCLEAR_OR_CONDITIONAL. A condition whose outcome does NOT change the action never blocks coding the action.
3. Two or more actions entertained without a direction (e.g. "either change or just cancel, not sure") → UNCLEAR_OR_CONDITIONAL.
4. No action direction stated → UNCLEAR_OR_CONDITIONAL.
Examples (e.g., never exhaustive): "We're sticking with the booking tonight." → KEEP_BOOKING · "I'll look up the reviews, but we'll probably still go." → KEEP_BOOKING · "I'd keep it if Friend A calms down, otherwise maybe cancel." → UNCLEAR_OR_CONDITIONAL · "Let's move it to the Italian place instead." → CHANGE_RESTAURANT · "Honestly I'd rather do it another week." → CANCEL_OR_POSTPONE.

BRT2_contingency_stated (0/1)
- 1 iff the response states at least one explicit outcome-contingent branch tying a check result to the MEDICATION action, in either direction (e.g. "if the articles check out, I won't take it"; "if my GP confirms it's safe, I'll start"; "if I find nothing solid, I'll take it as prescribed"). The branch must name a condition and an action. BRT2 emotion codes (0/1 each)

- BRT2_conspiracy_ideation — 1 iff the response asserts bad-faith or corrupt motives in the prescribing/medical/pharmaceutical system as a consideration: kickbacks or payment for prescribing (wondering counts), profit motives driving prescriptions, doctors knowingly pushing harmful drugs, categorical big-pharma malfeasance ("he's obviously getting a kick-back for prescribing poison", "the system compensates doctors who prescribe it", "all these approved chemicals are why people get cancer"). - BRT2_sceptic_grounded — 1 iff doubt toward the video/creator/claim comes with ANY articulated ground stated in the span.
